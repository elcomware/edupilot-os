# Workspace behavior

- **Access.** Sign in with school ID, email and password. Keep the bearer token only in memory. Reloading or reopening the tab requires sign-in. A 401 clears the session and all cached school data. A protected deep link returns to its requested destination after sign-in. Sign out clears the local session and cache immediately, attempts server revocation and reports when it cannot be confirmed.
- **Navigation.** The module directory, its pins, preferences and module pages share one shell. Group, search and pin controls operate on the signed-in user's server-provided catalog. Do not use client preferences to grant access. The server is authoritative for permissions and school isolation.
- **Collections.** Both record editors use a native modal with labeled fields, an explicit save and cancel, pending actions, and retained values on failure. Student creation/editing accepts given and family names; archival requires a named confirmation and version. Workspace entries create titles and update title/status using a version. Conflicts keep the draft visible until the user chooses to load the latest record. Browser history and reload warn before abandoning a dirty form. No automatic write retries or queued offline writes. The UI distinguishes a request rejected before sending from a write whose reply was lost. A dropped confirmation asks the operator to review current records before retrying.
- **Specialized work.** Enrollment places an active student in a grade for a consecutive academic year and uses the placement version to withdraw. Documents accepts supported files up to 8 MiB, returns the server ID and downloads by ID. An unconfirmed upload without an ID requires checking with an administrator before retrying.
- **Results.** Show server-confirmed results, live feedback, and distinct loading, empty, forbidden, missing, conflict and error states. Page through server data. Only show actions permitted by the catalog and principal. Show no fake sample rows or derived financial/operational claims.
- **Preferences.** Locale, theme, accent, density, width and pinned module order are cosmetic settings on this device, scoped to the current school and principal. Shell and Preferences consume the same ordered authorized catalog; unknown or unavailable saved keys never supply module metadata or access. Named up/down actions swap visible neighbors even across unavailable saved pins, apply to the rail immediately, and keep focus on the moved row. A failed catalog load makes ordering unavailable rather than claiming there are no saved pins; an empty authorized list points to the directory. Reset this workspace uses the shared confirmation Dialog: cancel preserves values; confirm removes only the current preference key and restores locale, appearance and pins to device defaults. It leaves other identities and authentication untouched. A failed removal keeps values and the confirmation open for retry. One localized live status reports confirmed storage changes or persistence limits; a failed save never claims durable success. Never persist records, credentials or tokens. System theme follows live OS changes. State may not survive device storage restrictions. Server-synced presets and group inheritance are outside this personal device setting.
- **Accessibility.** Semantic links, buttons, headings, landmark navigation, skip link, visible focus and native selects. Modal dialogs contain focus and restore it; their action remains pending after a failure. Use localized live feedback and preserve a usable logical focus target after removal. At narrow sizes navigation reflows and table headings remain available. Respect reduced motion.
