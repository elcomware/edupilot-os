# Starter ownership inventory

Baseline: `049c502536c43f8cefb4d804fab987e6d1855f39` (2026-11-06). This records Task 1 / TEN-02 inventory evidence only. It provides no integrated migration, multi-school enablement, tenant transfer registry or production readiness claim.

The source of truth is `bootstrap.Migrations()` plus `modules.Definitions()` and actual public wiring. There are **42 registered modules**, **41 `ws_*` work-list tables**, and the specialized Students register. Enrollment additionally owns placements. Module names such as tenancy, identity, permissions and users do not make their generic private work lists control-plane identity or a real topology model.

Current `school_id`, outbox `tenant_id`, placement pin `tenant_id`, pool-owner slug, session school and blob school prefix all mean the **legacy school**, not a new tenant. New tenant/org/school/campus/subject IDs are independent canonical random UUIDs; business record IDs remain byte-for-byte unchanged. A mapping must carry source pool provenance plus legacy school/user identifiers. Nullable scope is never wildcard authority. Control and shared data are physically co-located in the starter; dedicated pools still keep credentials, grants, native history and placement pins in control.

Each row names a concrete durable surface or format, its owner, identifiers and required later upgrade strategy. These are decisions for the later additive v2/offline-upgrade tasks, not implemented adapters. The architecture check derives tables from module DDL and discovers literal native/SQL creates in production sources; it rejects missing or duplicate entries and missing source paths. Native fixture checks additionally freeze actual registered descriptors and verify the exact durable table sets against `testdata/starter/tables.json` ownership, placement and legacy scope-column annotations.

## Storage and wiring decisions

- Original signatures, SQL, marker strings, receipt rows and connection suffixes are immutable. The native migration ledger lives on control; a target-local receipt commits with its DDL. The starter’s random marker is not a hierarchy identifier. Placement pins currently appear on first resolution; future normal runtime must become read-only and explicit provisioning/import owns placement creation.
- Private document bytes use local `storage/documents` (or configured root) and S3 object keys with exactly the same legacy path. Objects have no SQL metadata row, so “missing” means a known external reference without bytes and cannot be discovered by listing alone. A deployment upgrade needs both object enumeration and reference inventory; unavailable enumeration is an explicit blocker. Local staging `.upload-<uuid>` is unpublished/orphan evidence, never a downloadable document. S3 secrets and endpoint configuration are not tenant records and never belong in manifests/reports.
- `cmd/worker` round-robins all configured pools and `platform/outbox` performs delivery with a lease and transactional audit receipt. Existing pending leases, completed receipts, poison/dead events and already published messages survive any copy. Event IDs are only unique per original physical table; aggregate and user IDs are scoped by legacy school. Cross-pool event collisions require manifest resolution before consolidation.
- `app/jobs/expire_sessions.go` is the only registered native queue job and deletes expired control sessions. The default queue is synchronous; operator-selected database queues persist infrastructure work in `jobs` / `failed_jobs`. No tenant business payload currently uses this queue. This is a verified control-only classification, not a ban on future scoped jobs.
- Current student and enrollment application ports expose school-scoped public contracts; the inventory adds no cross-module private-table reads. A later UoW must scope every existing SQL workflow and outbox together. New grants, topology, object metadata and transfer records are deliberately absent from the actual starter inventory.
- Web principal/session/request state, mobile secure token restoration and Wails gateway requests carry legacy school context. Cosmetic preference keys are durable local data; private caches and object URLs are transient and must be invalidated, not imported as authoritative data. Gateway origins/allowlists are infrastructure configuration, not ownership grants.
